# PRD 写作规范

一份能开工的 PRD，六个部分缺一不可。**每部分都要能被下游直接使用**，不是给老板看的汇报稿。

## 1. 背景与目标

- 现状痛点：用一句具体的话，不用形容词。✅"月底对账要翻三天小票" ❌"效率低下"
- 本期目标：可量化，带时间和数字。✅"1 名店长 3 分钟内开完一单"
- **非目标**：必须有。写清本期不做什么，否则开发过程中范围一定膨胀
- 周期：给一个真实区间（2 周 MVP / 4 周），不要"尽快"

## 2. 用户与场景

按角色列，每个角色写三件事：**关注什么数、做什么动作、看什么报表**。

再写一个**核心场景**（一天怎么用），和一个**异常场景**（断网、重复提交、权限不够时怎么办）。

## 3. 功能清单

表格四列：编号 / 模块 / 优先级 / 主流程 / 异常与边界。

- 编号用 `FR-01` 起，验收标准用 `AC-01` 对应
- 优先级只分 P0（本期必须有）/ P1（本期尽量）/ P2（下期），**不要出现"重要且紧急"这种词**
- 每个模块的「异常与边界」至少覆盖四项：空列表、超限、重复提交、无权限

## 4. 交互与规则

这是研发真正在看的章节。每个模块写：

- **字段**：名称 + 类型 + 是否必填 + 长度/精度 + 校验
- **规则**：谁能改、什么时候能改、改了影响什么
- **权限**：角色 × 操作矩阵（谁能改价、删单、导出）
- **异常处理**：空数据引导、提交中禁用、失败保留草稿、越权前端隐藏+后端拒绝

字段规则要具体到能写代码：

| 差 | 好 |
|---|---|
| "金额要做校验" | "金额 > 0 且 ≤ 99999，保留 2 位小数，以分为单位存储" |
| "日期要合理" | "预约时间不得早于当前时间，最多提前 30 天" |

## 5. 验收标准

每条必须**可被测试执行**。写法：动作 + 结果 + 判定条件。

✅ "员工账号看不到改价入口；直接调接口返回 403"
✅ "列表首屏 ≤ 1.5s（1000 条数据），搜索响应 ≤ 500ms"
❌ "体验流畅" ❌ "功能正常" ❌ "满足业务需求"

## 6. 上线与埋点

- 灰度范围与时长
- 埋点：每个模块记「进入 / 操作成功 / 失败」三类事件
- 监控指标与告警阈值
- 回滚方案（数据要不要双写、多久）
- 数据字典：主键、审计字段、金额单位

## 三个最常见的漏项

1. **不写非目标** → 范围膨胀，二期永远排不上
2. **不写异常边界** → 上线后第一批 bug 全在这里
3. **验收写成感受** → 测试只能靠猜，最后"算不算通过"变成扯皮

## 语气

- 用行业词："桌台""卡项""案号""批号"，不要统一叫"数据"
- 短句，一条一个动作
- 禁止："赋能、抓手、闭环、生态、链路"——这些词对研发没有信息量

## 改稿规矩（重要）

用户说"把用户改成客户"时，**只改那一个词**，不要顺手"优化"整段。AI 改文档最常见的破坏就是把上下文一起重写。改完要能回答："我只动了这一处。"
