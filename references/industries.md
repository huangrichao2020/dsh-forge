# 行业字典维护

## 三个文件的关系

```
data/archetypes.json   原型模块库（20 个）：开单/会员/预约/库存/课程/工单/项目/
                       客户/排班/结算/合同/合规/报表/设备/排队/配送/质检/患者/处方
data/verticals.json    精选行业（20 个）：手调过模块名，质量最高
data/industries.json   行业元组（137 行）：引用原型组合，覆盖长尾
```

加载顺序：精选 20 个先入列；行业行逐个组合，**id 或名称与精选重复的自动跳过**（精选更具体）。

当前合计：**143 个行业 / 613 个模块**。

## 加一个行业

在 `data/industries.json` 的 `rows` 里加一行：

```json
["coldchain", "冷链", "company", "冷库 / 冷链运输 / 生鲜", "#2C7A7B", "运营经理",
 "温控记录、库容调度、货损", "在途车次,温控达标,库容占用,货损率",
 "delivery,inventory,asset,report"]
```

九列依次是：

| # | 字段 | 说明 |
|---|---|---|
| 1 | `id` | 小写英文，唯一 |
| 2 | `label` | 中文行业名，用于 `--vertical` 匹配 |
| 3 | `kind` | `store` 门店 / `company` 公司 |
| 4 | `subtitle` | 细分场景，斜杠分隔 |
| 5 | `accent` | 行业主色 hex |
| 6 | `persona` | 主要使用者角色 |
| 7 | `pain` | 一句话痛点（具体，不写"效率低"） |
| 8 | `kpis` | 4 个首页指标，逗号分隔 |
| 9 | `archetypes` | 模块组合，从原型库挑 3~6 个，逗号分隔 |

第 10 列可选 `tweaks`，只改某个原型的名称/描述：

```json
["hotpot", "火锅", "store", "川渝火锅 / 潮汕牛肉", "#C53030", "店长",
 "锅底翻台慢、会员卡沉睡", "今日营业额,翻台率,储值余额,会员新增",
 "order,member,inventory,queue,report",
 { "queue": ["排队叫号", "取号 / 叫号 / 等位"] }]
```

## 加一个原型

当某类模块在多个行业反复出现（≥3 次），再抽成原型；否则先写在行业 `tweaks` 里，别急着抽象。

```json
"delivery": { "name": "配送履约", "desc": "派单、在途、签收",
  "fields": ["运单", "地址", "骑手", "状态"], "actions": ["派单", "签收"] }
```

`fields` 决定列表列与表单字段，**最多 4 个**（多了页面放不下）。字段名要能被 `valueFor()` 识别语义，否则会生成"待定"。新增语义前缀时同步补 `lib/core.mjs` 的 `valueFor()`。

## 什么时候升级为精选

一个行业出现这些情况时，从 `industries.json` 搬到 `verticals.json`：

- 模块名和实际业务对不上（原型叫"工单派工"，实际叫"洗车排队"）
- 需要行业专属 KPI
- 已经给 3 个以上客户用过

精选行业的模块是手写的，可以完全脱离原型。

## 常见坑

1. **id 冲突**：新行业 id 撞了精选，会被静默跳过——加完跑一次 `node build.mjs verticals --query <新行业>` 确认能看到
2. **原型不存在**：`archetypes` 里写错 key 会被跳过（不报错），模块数会少；组合后模块数 < 3 要检查
3. **KPI 超过 4 个**：只取前 4 个
4. **字段名语义缺失**：导致演示数据出现占位符，见 `references/demo-spec.md` 的数据规则
